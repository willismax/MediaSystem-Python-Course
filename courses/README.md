# 多媒體系統：雙軌課程架構

本 repository 採「**一個素材庫、兩條教學路線、共同專題規格**」的方式兼容兩門同名但主軸不同的課程。不要複製整份 repository，也不要強迫兩班依相同章節順序上課。

## 課程入口

- [日間部四技一年級：媒體素養與實作](day/README.md)
- [進修部一年級：Python、API 與雲端應用](evening/README.md)

## 三層內容模型

| 層級 | 放置內容 | 維護方式 |
|---|---|---|
| 課程層 `courses/` | 班別定位、週次建議、必修／選修、評量與外部講義入口 | 每學期調整課程地圖，不複製教材 |
| 模組層（既有編號目錄） | Notebook、範例程式、實作說明 | 跨班共用；每份教材只有一個來源 |
| 學期層（GitHub Release／tag） | 當學期可重現的教材快照 | 建議使用 `day-YYYY-termN`、`evening-YYYY-termN` 標籤 |

HackMD 適合即時公告、課堂補充與書本模式導覽；GitHub 適合版本化的程式與作業。HackMD 應連回固定檔案或 tag，避免再貼一份程式碼而產生不同版本。

## 共用課程能力

兩班採不同入口，但在下列能力會合：

1. 能說明一項數位媒體或網路資料的格式與限制。
2. 能用 Python 讀取、轉換並呈現資料或媒體。
3. 能組合至少一個外部 API、媒體處理或互動介面。
4. 能以 README 說明來源、授權、執行方法、分工與測試結果。
5. 能展示一個可重現的分組專題，而不只繳交簡報。

## 建議的維護流程

1. **保留既有目錄與網址**：目前大量講義可能已連到 `01.Intro-Python` 等路徑；只新增課程地圖，不做破壞性搬移。
2. **新教材先判斷是否共用**：共用教材放模組層；只有班別說明、週次或評量才放 `courses/day` 或 `courses/evening`。
3. **以狀態標記範圍**：每條路徑明列「核心、選修、延伸」，不要用資料夾編號暗示所有內容都必教。
4. **學期開始建立 issue／project**：以週為 milestone，教材改善用 issue 追蹤；不要建立長期分歧的日間部與進修部 branch。
5. **學期結束建立 tag 或 Release**：保存當期快照；下一學期仍由預設 branch 改進共用教材。
6. **作業另用 template repository 或 Classroom**：學生專題不提交到教材庫，降低 pull request 與答案互相污染。

## 新內容命名規則

未來可逐步補上 `media/`（影像、音訊、視訊、編碼與著作權）及 `cloud/`（HTTP、API、部署與觀測）等語意化模組。新增時應提供：

- 模組 README（目標、先備知識、預估時間、課前／課後活動）。
- 可在 Colab 或本機重現的範例，以及明確依賴版本。
- 素材來源與授權；API key 一律透過環境變數或範例設定檔，不可提交真實密鑰。
- 對應到兩條課程地圖的核心／選修標記。

- [ ] 專題 rubric 同時評量「概念理解、可執行成果、文件、分工與展示」。
